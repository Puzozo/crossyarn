# SEO-план блогу Crossyarn

> Статус: **план** (блог `/blog`, `/blog/[slug]` ще не реалізований у коді — цей документ описує майбутню структуру та контент). Код не змінюється.
> Канонічний домен: `https://crossyarn.online`. Мови: `uk` (основна) + `en`.
> Ціль блогу: органічний трафік із ніші «схеми для в'язання» → реєстрація в редакторі `/editor` та перегляд каталогу `/explore`.

---

## 1. Стратегія і принципи

- **Pillar–cluster модель.** Кожен тематичний кластер має одну опорну (pillar) сторінку під широкий запит і 3–6 підтримувальних статей під вужчі запити; усі підтримувальні лінкують на pillar і одна на одну.
- **Пошуковий намір.** Блог закриває *інформаційний* намір (як в'язати, що означають символи), а продукт (`/editor`, `/explore`) — *транзакційний/навігаційний*. Кожна стаття веде читача від «як зробити» до «зроби це у нас».
- **Двомовність.** UA і EN — окремі URL зі slug відповідною мовою, зв'язані `hreflang` (`uk` / `en` + `x-default`). Не змішувати мови на одній сторінці.
- **E-E-A-T.** Авторство (посилання на публічний профіль `/u/[username]`), дати оновлення, практичні приклади зі скриншотами схем із каталогу.
- **Внутрішня перелінковка — основний важіль.** Кожна стаття обов'язково лінкує щонайменше на (1) релевантний фільтр каталогу `/explore?tag=...`, (2) редактор `/editor`, (3) 1–2 суміжні статті блогу.

## 3. URL-структура блогу

```
/blog                       — індекс блогу (список статей, newest first, пагінація ?page=)
/blog/[slug]                — стаття (uk)
/blog/[slug]                — стаття (en) з en-slug; мова визначається slug + <html lang>, зв'язок через hreflang
/blog?tag=[cluster]         — (опційно) фільтр за кластером/тегом статей
```

**Правила slug:**
- Латиниця, kebab-case, без дат і без `.html`; стабільний і незмінний після публікації (зміна → 301).
- UA-slug — транслітерація або англомовний смисловий (рекомендовано англомовний смисловий для чистоти URL), EN-slug — англійською.
- Канонічний URL на кожній сторінці; `robots: index,follow` для опублікованих, `noindex` для чернеток.

**Технічне (для майбутньої реалізації, поза цим планом):**
- Додати `/blog` і `/blog/[slug]` у `src/app/sitemap.xml` (revalidate як у патернів).
- OG-теги та `metadataBase` вже є у `src/lib/site.ts` — переюзати для `/blog`.
- `hreflang` — через `alternates.languages` у `generateMetadata`.

## 4. Три стартові статті

### Стаття 1 — Кластер A (верх воронки, UA)

- **Slug:** `/blog/how-to-read-knitting-chart`
- **Цільовий запит:** «як читати схему для в'язання» (+ «умовні позначення спицями»)
- **Title (≤60 симв.):** `Як читати схему для в'язання: повний гайд для початківців — Crossyarn`
- **Meta description (≤155 симв.):** `Пояснюємо умовні позначення, напрямок читання рядів і раппорт. Навчіться читати будь-яку схему спицями за 10 хвилин.`
- **H1:** Як читати схему для в'язання
- **План H2/H3:**
  - H2: Що таке схема і з чого вона складається
  - H2: Напрямок читання: ряди, стовпці, лицьові та виворітні
  - H2: Основні умовні позначення (з таблицею символів)
    - H3: Лицьові, виворітні, накиди
    - H3: Схрещення (коси) та зняті петлі
  - H2: Що таке раппорт і як його повторювати
  - H2: Як рахувати ряди й не загубитися (режим в'язання на `/p/[id]`)
  - H2: Практика: відкрийте готову схему й спробуйте самі
- **Внутрішні посилання:**
  - `/explore?tag=для-початківців` — прості схеми для тренування
  - `/explore` — весь публічний каталог
  - `/editor` — «створіть власну схему»
  - Стаття 2 (жаккард) і Стаття 3 (редактор) як «читати далі»
  - `/p/[id]` — приклад готової схеми з режимом в'язання

### Стаття 2 — Кластер B (середина воронки, UA)

- **Slug:** `/blog/fair-isle-jacquard-charts`
- **Цільовий запит:** «схема жаккарда спицями» (+ «норвезькі візерунки схеми»)
- **Title:** `Жаккард спицями: як читати і складати схеми — Crossyarn`
- **Meta description:** `Розбираємо кольорові жаккардові схеми: сітка, протяжки, кількість кольорів у ряду. Приклади норвезьких візерунків і готові схеми.`
- **H1:** Жаккард спицями: читаємо і складаємо схеми
- **План H2/H3:**
  - H2: Чим жаккардова схема відрізняється від однотонної
  - H2: Як читати кольорову сітку (клітинка = петля певного кольору)
  - H2: Скільки кольорів у ряду — і чому це важливо для протяжок
  - H2: Норвезькі та скандинавські мотиви: типові раппорти
  - H2: Як перенести картинку чи орнамент у схему
    - H3: Вручну по клітинках у редакторі
    - H3: Поради щодо розміру сітки й палітри
  - H2: Готові жаккардові схеми в каталозі
- **Внутрішні посилання:**
  - `/explore?tag=жаккард` — жаккардові схеми
  - `/explore?tag=орнамент` — орнаменти/норвезькі мотиви
  - `/editor` — «складіть власний жаккард» (згадати палітру кольорів, раппорти)
  - Стаття 1 (як читати схему) — для початківців
  - Стаття 3 (редактор) — як оцифрувати мотив

### Стаття 3 — Кластер E (низ воронки, UA)

- **Slug:** `/blog/create-knitting-chart-online`
- **Цільовий запит:** «створити схему для в'язання онлайн» (+ «редактор схем в'язання», «програма для схем спицями безкоштовно»)
- **Title:** `Як створити схему для в'язання онлайн безкоштовно — Crossyarn`
- **Meta description:** `Покроково: малюєте сітку, додаєте символи й кольори, зберігаєте раппорти та експортуєте схему в PDF. Безкоштовний онлайн-редактор.`
- **H1:** Як створити схему для в'язання онлайн
- **План H2/H3:**
  - H2: Навіщо оцифровувати схему (зберігання, редагування, друк)
  - H2: Крок 1. Створюємо сітку потрібного розміру
  - H2: Крок 2. Малюємо символами й кольорами
    - H3: Палітра символів і заливка (bucket fill)
    - H3: Багатоклітинкові символи
  - H2: Крок 3. Раппорти — повторювані мотиви
  - H2: Крок 4. Пропуск виворітних рядів і нумерація
  - H2: Крок 5. Експорт у PDF/SVG і друк
  - H2: Крок 6. Публікація та приватність (PRIVATE / UNLISTED / PUBLIC)
- **Внутрішні посилання:**
  - `/editor` — головний CTA, «почати зараз» (кілька разів у тексті)
  - `/explore` — надихнутися чужими публічними схемами
  - `/account` — кастомні символи та профіль автора
  - Стаття 1 (як читати схему) і Стаття 2 (жаккард) — «що далі»
  - `/u/[username]` — приклад публічного профілю автора

## 5. Дорожня карта контенту (після 3 стартових)

1. Опорні (pillar) сторінки для кластерів A і E — оптимізувати під широкий запит, зібрати на себе підтримувальні статті.
2. EN-версії трьох стартових статей (ті самі H2, en-slug, hreflang) — кластери A, B, E.
3. Підтримувальні статті кластерів C (коси) і D (ажур) — по одній pillar + 2–3 supporting.
4. «Словник умовних позначень» як вічнозелена довідкова сторінка з якорями — ціль внутрішніх посилань з усіх статей кластера A.

## 6. Чек-ліст на кожну статтю

- [ ] Унікальні `title` (≤60) і `description` (≤155), один H1, логічна ієрархія H2/H3.
- [ ] Канонічний URL + `hreflang` для парної мовної версії.
- [ ] ≥3 внутрішні посилання: `/explore?tag=...`, `/editor`, суміжна стаття.
- [ ] 1–2 CTA на редактор `/editor` у тілі статті.
- [ ] Зображення схем з `alt`, бажано з реальних публічних схем каталогу.
- [ ] Автор + дата оновлення (E-E-A-T), посилання на `/u/[username]`.
- [ ] Структуровані дані `Article`/`BlogPosting` (JSON-LD) при реалізації.
